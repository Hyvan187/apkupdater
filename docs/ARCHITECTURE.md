# UniAPK architecture

- `UpdatesRepository` queries enabled metadata providers. `SourceHealth` distinguishes failure, cancellation and web-only availability. Results retain per-source identity and real installation facts. Equal visible versions and non-newer codes are reconciled before presentation.
- `UpdatesViewModel` coordinates foreground discovery, temporary batch inspection, explicit single preparation and installation with `UpdateOperations`. The periodic worker shares that gate. `PackageProcess` exposes real byte progress, actual analysis and terminal evidence; a prepared file remains separate from metadata-only findings.
- `AutomaticDownloads` is off by default, requires a persisted writable tree and observes network/count/size/storage budgets. Bounded saved-version receipts avoid repeatedly fetching a still-readable managed public copy. Receipts never grant installation approval.
- `ApkSetInspector` and `ApkAnalyzer` parse bounded binary manifests and verify actual signatures and set consistency. Installation repeats the check on private bytes and then requires Android confirmation. Physical PackageManager versions are the success criterion. Optional external handlers have explicitly observed rather than assumed outcomes.
- `DownloadArchive` publishes only explicitly wanted/opted-in files, reuses identical hashes and removes managed copies only after confirmed success when configured. Temporary batch inspections do not publish. `AppCache` leases protect active operations; cache maintenance never deletes settings, private diagnosis, public downloads or pending installer handoffs.
- `ResourcePolicy` bounds raw downloads against available space and reserves capacity for temporary installation copies. `ComputeBudget` controls app-owned computational concurrency; Android remains responsible for renderer, UI and network thread scheduling.
- `DeviceDetection` reads explicit firmware/CSC signals without SIM/locale guessing. `TestDeviceProfiles` contains public product metadata with source references, independent of any user's own phone. Product and regional selection affect supported store request hints; actual compatibility never adopts simulated device facts.
- `SourceCredentials` runs at each network exchange and scopes credentials to the intended HTTPS host. Preferences use Android Keystore encryption. No build includes user tokens or private signing material.
- `DiagnosticStore` is a bounded, age-limited JSONL ring. `AppDiagnostics` serializes writes and records losses. General exports strip technical profiles and free-text messages; detailed capture/export requires UI consent. Export uses a caller-chosen document URI, separate from private automatic recording.
- `AppearanceStore` previews controls before persistence. Full-window animations pause with lifecycle/accessibility/power constraints and respond to the computational budget. Glass dialogs share the same transparent hosts. Adaptive/monochrome icons use explicit mask safety margins.

Host tests use actual signed, code-free APK fixtures. Only PackageManager archive metadata is injected on hosts where the native Android archive parser cannot run normally; manifest/signature/set verification still processes real bytes. Device-specific installer and live store behavior require physical acceptance.
